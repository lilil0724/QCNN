## OD-001：Baseline／Oracle code-scale decomposition

- 日期：2026-08-30
- 狀態：完成
- 工具：`tools/eval_oracle_decomposition.py`
- Evaluation：WikiText-2 raw test split，共用 Bonsai skeleton，sequence length 2048
- 目的：分離 ternary code 與 group scale 對功能性 NLL/PPL 的影響。

### 原始結果

| Mode | Code source | Scale source | NLL ↓ | PPL ↓ |
|---|---|---|---:|---:|
| `baseline_code_baseline_scale` | baseline | baseline | 13.688487 | 880,713.000 |
| `oracle_code_baseline_scale` | oracle | baseline | 8.599812 | 5,430.636 |
| `baseline_code_oracle_scale` | baseline | oracle | 12.164909 | 191,934.297 |
| `oracle_code_oracle_scale` | oracle | oracle | 2.874553 | 17.718 |

### 衍生結果

Baseline-to-oracle NLL gap 為 `10.813934`。

| Effect | NLL improvement | Total gap closure |
|---|---:|---:|
| Oracle code，固定 baseline scale | 5.088675 | 47.1% |
| Oracle scale，固定 baseline code | 1.523578 | 14.1% |
| Code-scale interaction | 4.201681 | 38.9% |

### 解讀

Code 是較大的單一瓶頸，但 oracle code 搭配 baseline scale 的 PPL 仍為 5,430.636，
顯示正確 code 與相容 scale 必須共同存在。交互作用很大，不應把 code 與 scale 視為完全
獨立的功能性問題。

## WM-S009：ContextMLP prediction model

- 日期：2026-08-31
- 狀態：完成
- Serial：9
- Architecture：`context_mlp`
- Parameters：0.04M
- Seed：0
- Train/validation layers：147／49
- Split：`depth % 4 == 3` 為 validation，其餘為 training
- 主要參數：hidden 128、20 epochs、500 steps/epoch、batch size 64、segment length 512、
  group size 128、AdamW、learning rate `3e-4`、weight decay `0.01`、scale weight `0.1`、
  hard weight `1.0`、128 evaluation rows/layer
- 輸出：`results/serial9/`
- Checkpoint：`results/serial9/best_context_mlp.pt`

### 最佳結果

| Metric | Value |
|---|---:|
| Best epoch | 15 |
| B1 validation accuracy | 0.6119 |
| Best validation accuracy | 0.6229 |
| Absolute accuracy improvement | +0.0110 |
| Hard fraction | 0.3881 |
| Hard accuracy | 0.2050 |
| Scale relative error at selected checkpoint | 0.1338 |

### 訓練行為

- Epoch 7 後 validation accuracy 約落在 0.621–0.623，呈現穩定 plateau。
- 最低觀察到的 scale relative error 為 0.1249（epochs 14、16），但目前 checkpoint 只依
  overall validation accuracy 選擇，因此保存的是 epoch 15。
- 結果與先前 A0 約 0.623 的紀錄一致；local-feature ContextMLP 只小幅超越 B1／B2。
- 模型修正部分 hard entries，也破壞部分原本正確的 easy entries；平均 code accuracy 的
  小幅提升是否有功能價值，需由 decomposition 判斷。

## PD-S009：ContextMLP predicted decomposition

- 日期：2026-08-31
- 狀態：完成
- Prediction checkpoint：`results/serial9/best_context_mlp.pt`
- 工具：`tools/eval_oracle_decomposition.py`
- Evaluation：與 OD-001 相同的模型 skeleton、資料與 sequence length
- GPU batch size：1

### 執行事件

第一次以 batch size 4 執行時 CUDA OOM。RTX 5060 Ti 只有 16 GB VRAM；
`[4, 2048, 151669]` 的 float32 vocabulary logits 單獨約需 4.63 GiB。程序結束後顯存正常
釋放。將 batch size 降為 1 後完成；batch size 不改變 NLL/PPL 定義。

### 原始結果

| Mode | Code source | Scale source | NLL ↓ | PPL ↓ |
|---|---|---|---:|---:|
| `predicted_code_oracle_scale` | predicted | oracle | 12.031057 | 167,888.844 |
| `oracle_code_predicted_scale` | oracle | predicted | 5.506246 | 246.225 |
| `predicted_code_predicted_scale` | predicted | predicted | 12.928100 | 411,720.750 |

### 七種已完成模式總表

| Code | Scale | NLL ↓ | PPL ↓ | NLL gain vs. baseline | Total gap closure | NLL gap to oracle |
|---|---|---:|---:|---:|---:|---:|
| baseline | baseline | 13.688487 | 880,713.000 | 0.000000 | 0.0% | 10.813934 |
| baseline | oracle | 12.164909 | 191,934.297 | 1.523578 | 14.1% | 9.290356 |
| predicted | oracle | 12.031057 | 167,888.844 | 1.657430 | 15.3% | 9.156504 |
| predicted | predicted | 12.928100 | 411,720.750 | 0.760387 | 7.0% | 10.053547 |
| oracle | baseline | 8.599812 | 5,430.636 | 5.088675 | 47.1% | 5.725259 |
| oracle | predicted | 5.506246 | 246.225 | 8.182241 | 75.7% | 2.631693 |
| oracle | oracle | 2.874553 | 17.718 | 10.813934 | 100.0% | 0.000000 |

### Component 分析

| Comparison | NLL improvement | Interpretation |
|---|---:|---|
| baseline code → predicted code，固定 oracle scale | 0.133852 | 只恢復約 1.44% 的 conditional code opportunity |
| baseline scale → predicted scale，固定 oracle code | 3.093566 | 恢復約 54.0% 的 conditional scale gap |
| baseline/baseline → predicted/predicted | 0.760387 | 完整 predictor 關閉 7.0% total gap |
| predicted/predicted → oracle/oracle | 10.053547 | 完整 predictor 仍遠離 oracle |

### 解讀與後續

- ContextMLP 的 code accuracy 雖提高 1.10 percentage points，但對 NLL 的改善很小；
  平均 code accuracy 沒有捕捉功能敏感位置。
- Scale predictor 在 oracle code 下具有明顯訊號，但搭配錯誤 predicted code 時效果惡化，
  顯示兩個 heads 尚未協調。
- 下一步：以相同 protocol 評估 GroupConv、多 seed 重跑、補齊缺少的
  `baseline_code_predicted_scale` 與 `predicted_code_baseline_scale`，並考慮 joint
  reconstruction loss 與 layer-sensitivity-weighted code loss。

- 日期：2026-08-31
- 狀態：完成
- Serial：10
- Architecture：`group_conv`
- Parameters：0.51M
- Seed：0
- Train/validation layers：147／49
- Split：`depth % 4 == 3` 為 validation，其餘為 training
- 主要參數：hidden 128、20 epochs、500 steps/epoch、batch size 64、segment length 512、
  group size 128、AdamW、learning rate `3e-4`、weight decay `0.01`、scale weight `0.1`、

- 輸出：`results/serial10/`

### 最佳結果

輸出中 epoch 18 標有最後一次 `<- best`；epoch 19 顯示相同四位小數，但未超過未四捨五入的
最佳值，因此保存的 checkpoint 對應 epoch 18。

| Metric | Value |
|---|---:|
| Selected checkpoint epoch | 18 |
| B1 validation accuracy | 0.6119 |
| Best validation accuracy | 0.6243 |
| Absolute accuracy improvement over B1 | +0.0124 |

| Scale relative error at selected checkpoint | 0.1262 |

### 與 ContextMLP serial 9 比較

| Metric | ContextMLP S009 | GroupConv S010 | GroupConv difference |
|---|---:|---:|---:|
| Parameters | 0.04M | 0.51M | 約 12.8× |
| Best validation accuracy | 0.6229 | 0.6243 | +0.0014 |
| Hard accuracy at selected checkpoint | 0.2050 | 0.1876 | -0.0174 |
| Scale relative error at selected checkpoint | 0.1338 | 0.1262 | -0.0076 |

### 解讀與後續

- 訓練正常收斂，epoch 9 後 validation accuracy 約為 0.623–0.624，沒有發散。
- GroupConv 以約 12.8 倍參數量換得 0.14 percentage point 的 validation accuracy 增益；
  在尚無 multi-seed variance 前，不能宣稱卷積結構實質優於 ContextMLP。
- Selected checkpoint 的 scale relative error 優於 ContextMLP，但 hard accuracy 較低；目前
  只依 overall accuracy 選模，不代表此 checkpoint 的功能 NLL 最佳。
- 下一步使用完全相同的 WikiText-2、sequence length 2048、batch size 1 protocol 執行
  GroupConv code-scale decomposition，重點比較 `predicted_code_predicted_scale` NLL 是否
  低於 ContextMLP 的 12.928100。

- Evaluation：與 OD-001／PD-S009 相同的模型 skeleton、WikiText-2 與 sequence length 2048

### 原始結果

| Mode | Code source | Scale source | NLL ↓ | PPL ↓ |
|---|---|---|---:|---:|
| `baseline_code_baseline_scale` | baseline | baseline | 13.688487 | 880,713.000 |
| `oracle_code_baseline_scale` | oracle | baseline | 8.599812 | 5,430.636 |
| `baseline_code_oracle_scale` | baseline | oracle | 12.164909 | 191,934.297 |
| `oracle_code_oracle_scale` | oracle | oracle | 2.874553 | 17.718 |
| `predicted_code_oracle_scale` | predicted | oracle | 11.876951 | 143,911.125 |
| `oracle_code_predicted_scale` | oracle | predicted | 5.479738 | 239.784 |
| `predicted_code_predicted_scale` | predicted | predicted | 11.310417 | 81,667.891 |

### 工具輸出的 NLL contrasts

| Contrast | NLL difference |
|---|---:|

### 衍生結果

| Metric | Value |
|---|---:|
| Baseline-to-oracle NLL gap | 10.813934 |
| Full predicted total gap closure | 22.0% |
| Baseline/full-predicted PPL ratio | 10.8× |
| Predicted-code conditional opportunity recovered under oracle scale | 3.1% |
| Predicted-scale conditional gap closed under oracle code | 54.5% |
| Predicted scale gain under predicted code | 0.566534 NLL |

### 與 ContextMLP PD-S009 比較

| Mode | ContextMLP NLL | GroupConv NLL | GroupConv improvement | ContextMLP PPL | GroupConv PPL |
|---|---:|---:|---:|---:|---:|
| predicted code + oracle scale | 12.031057 | 11.876951 | 0.154106 | 167,888.844 | 143,911.125 |
| oracle code + predicted scale | 5.506246 | 5.479738 | 0.026508 | 246.225 | 239.784 |
| predicted code + predicted scale | 12.928100 | 11.310417 | 1.617683 | 411,720.750 | 81,667.891 |

### 解讀與後續

- GroupConv 的 full predicted NLL 比 ContextMLP 低 1.617683，PPL 約低 5.0 倍；相較
  baseline/baseline 關閉 22.0% total NLL gap，而 ContextMLP 只關閉 7.0%。
- 兩模型 validation accuracy 僅差 0.0014，但功能結果差異很大，證明平均 code accuracy
  不是可靠的 model-selection proxy；錯誤位置與 code-scale 相容性比平均正確率更重要。
- GroupConv 的 predicted scale 在 predicted code 下進一步改善 0.566534 NLL；ContextMLP
  的 predicted scale 在 predicted code 下反而惡化 0.897043 NLL。這支持 GroupConv 的兩個
  heads 學到較相容的聯合輸出，但仍需 multi-seed 驗證。
- Code predictor 在 oracle scale 下只恢復 3.1% conditional code opportunity，仍是主要
  限制。Full predicted PPL 81,667.891 遠高於 oracle 17.718，零樣本轉換仍不可用。
- 下一步優先做 GroupConv／ContextMLP multi-seed，以及保存或選擇能反映 joint
  reconstruction／functional quality 的 checkpoint，而非只依 overall code accuracy。
