1. 範圍與術語

最重要的界線：本 repo 沒有重新執行或重現 Prism ML 的 Bonsai 原始 QAT。這裡訓練的是一個輔助 weight-map，學習從 Qwen3 全精度 block weights 預測 Bonsai 公開成品的 ternary code 與 group scale。

本文中的「訓練」均指本 repo 的 FP-to-ternary weight-map 訓練，不是 Bonsai 生產訓練。Prism ML 公開了 ternary g128 成品表示，但未公開可重現的資料、optimizer、STE、蒸餾目標或 schedule。

3

4

4. Ground-truth pair 建立

4.1 Tensor 配對

抽取器只接受名稱包含 .layers.、以 .weight 結尾、為 2-D，且 base／target 同名同形狀的 tensors。每個 matrix 獨立輸出為 safetensors shard。

4.2 Family assertion

Target tensor reshape 為 [out_features, in_features/128, 128]。每組非零 magnitude 的最大相對 spread 必須 ≤ 2%；exact-zero fraction ≤ 0.001 判為 binary，≥ 0.02 判為 ternary。門檻是資料驗證政策，不是 Prism ML 的量化公式。

4.3 Code 與 scale 恢復

Ti = sign(Gi)   ·   ŝg = median({ |Gi| : Gi ≠ 0, i ∈ g })

全零 group 的 scale 設為 0，並從 scale loss 遮蔽。若任何非零 magnitude 相對於 group median 的偏差超過 2%，抽取立即停止。

Shard 欄位資料型別／內容用途
baseQwen3 原始浮點矩陣模型輸入
codeint8，{-1, 0, +1}三分類 ground truth
scalesfloat32，每 g128 一個scale regression ground truth
row / column statsabsmean 與 L2 norm輸入特徵
manifest.csvlayer、type、proj id、depth、shape、sparsity、reconstruction error資料索引與稽核

6. 每個 weight element 的 19 個輸入 channels

Element / group · 4
signed weight ÷ group absmean、absolute ratio、group 內 magnitude percentile rank、weight ÷ group absmax。
Group statistics · 3
group absmean ÷ tensor absmean、group absmax ÷ group absmean、group std ÷ group absmean。
Row / column · 4
row absmean、column absmean、normalized row L2 norm、normalized column L2 norm。
Conditioning · 8
normalized decoder depth，加七種 projection identity one-hot。

適合表示為正值比例的 statistics 取 log-ratio 並 clamp 至 [-8, 8]。Signed ratio、percentile rank、depth 與 one-hot 不取 log。

Inductive bias：模型允許使用 quantization group、同 row 的 column locality、跨 rows 彙整出的 column statistics；刻意不編碼 output-row adjacency，因為神經元列順序不具有影像像素式鄰近語意。

7. Weight-map 架構

A0 · ContextMLP

Null-hypothesis model：每個 element 獨立處理其 19 維特徵；不學習相鄰 columns 的交互作用。

  • Conv1d(19 → 128, kernel=1) + GELU
  • Conv1d(128 → 128, kernel=1) + GELU
  • Conv1d(128 → 128, kernel=1) + GELU
  • zero-init code / scale heads

A1 · GroupConv1D

沿同一 output row 的 column axis 建模；dilation 16 的單層覆蓋約 129 columns，接近一個 g128。

  • Conv1d(19 → 128, kernel=9) + GELU
  • Residual Conv1d(kernel=9, dilation=1)
  • Residual Conv1d(kernel=9, dilation=4)
  • Residual Conv1d(kernel=9, dilation=16)
  • zero-init code / scale heads

Decision-space residual

ẑ = 4 · one_hot(TB1) + Δzθ    ·    log ŝ = log sB1 + Δℓθ

兩個 heads 均 zero-initialized，因此未訓練模型精確輸出 B1。Scale residual 在原空間等價於 ŝ = sB1 exp(Δℓ)，即對 baseline scale 做乘法修正。

8. Loss、optimizer 與正式超參數

ℒ = ℒCE(T̂, T) + 0.1 · ℒHuber(log ŝ, log s)

Code loss 是 {-1, 0, +1} 三分類 cross-entropy。Scale loss 只在 true scale > 0 的 groups 上計算。正式 runs 使用 hard_weight=1.0，不額外放大 B1 錯誤位置。

9. Validation 指標與 checkpoint selection

每個 epoch 對 49 個 held-out matrices 執行固定 validation sweep，逐 element／group 累積：

指標定義與角色
Overall code accuracy所有 validation code positions 的正確率；正式選模標準。
B1 baseline accuracy同一 validation sample 上的 per-group absmean baseline。
Hard fractionB1 與 Bonsai ground truth 不一致的位置比例。
Hard accuracy模型在 hard subset 上修正成功的比例；只作診斷，不作正式選模。
Scale relative error|ŝ − s| / s，只對 true scale > 0 的 groups。

只有當本 epoch 的 overall validation accuracy 創新高時，才保存 best_{arch}.pt 與對應的 per-layer report。

10. 已執行的校正與 ablation

以下工作用來確認訓練框架與策略，與正式流程分開報告：

實驗目的結論
Single-tensor overfit確認資料、features、heads、loss 與 optimizer 能在真實 tensor 上工作。屬 framework correctness / learnability ceiling 檢查。
hard_weight=4強迫模型優先修正 B1 錯誤位置。Hard accuracy 約 0.73，但 overall 約 0.45，低於 B1 約 0.61；因破壞 easy positions 而捨棄。
LR sweep比較預設 3e−4 與已排程的 1e−3、3e−3 points。正式方法仍以文件化的 3e−4 設定報告；各 run artifacts 應另行歸檔。
A0 vs A1檢驗 handcrafted statistics 與 column-locality 的額外價值。A1 僅非常小幅領先 A0，局部卷積訊號有限。
Binary-pair runs同一框架對 binary Bonsai family 的適用性檢查。已排入並執行流程；本文核心量化結果仍聚焦 ternary pair。

11. 完整模型組裝與 functional evaluation

所有 variants 使用同一個真實 Bonsai skeleton，因此 tokenizer、embedding、norms 與 LM head 固定；只替換 manifest 中的 196 個 block projection weights。

Mode替換後的 block weights
fpQwen3 base block weights；因此是 Bonsai 外殼加 Qwen3 blocks 的 hybrid control。
oracle恢復出的 Bonsai true code × true scale。
naive_b0Qwen3 per-tensor absmean code × per-tensor kept-magnitude mean scale。
naive_b1Qwen3 per-group-128 absmean code × group baseline scale。
predicted最佳 A1 weight-map 預測 code × predicted group scale。

WikiText-2 PPL protocol

使用 raw test split，串接非空文本後切成不重疊的 2048-token windows；對 shifted targets 計算 token-weighted mean NLL，再取 PPL = exp(NLL)。CLI 預設 batch size 4、最多 200 windows；保存的實跑使用 145 個 windows。

13. 證據、重現性與論文揭露

Artifact 狀態：上述 aggregate numbers 來自 repo 內保存的實跑紀錄；目前本機工作樹未包含對應 raw CSV、完整 logs 與 model checkpoints。因此結果屬於「文件可追溯、原始 artifacts 待歸檔」。
  • 目前核心結果是單一 1.7B ternary pair、單一 vendor／recipe、single seed。
  • Validation 是同模型內 held-out depths，不是跨 scale 或跨 architecture。
  • Weight-map 只覆蓋 196 個 block projections，不覆蓋 embedding、LM head 或 norms。
  • PPL variants 共用 Bonsai skeleton；fp 是 hybrid control，不是原生 Qwen3。
  • 靜態 code accuracy 不等於 activation similarity，也不保證語言模型功能。

主要 repo 證據

  1. weight2ternary/data_utils/extract.py：matched tensor extraction、code／scale recovery、manifest。
  2. weight2ternary/data_utils/sampler.py：depth split、training sampling、validation sweep。
  3. weight2ternary/data_utils/features.py：19-channel feature contract。
  4. weight2ternary/model_utils/build_model.py：A0／A1 與 residual heads。
  5. weight2ternary/model_utils/losses.py：CE + log-scale Huber loss。
  6. tools/train_weight_map.py：optimizer、scheduler、超參數與 checkpoint selection。
  7. weight2ternary/eval_utils/assemble.py、tools/eval_perplexity.py：組裝與 PPL。
  8. docs/MASTER_PLAN_WEIGHT_MAP.md：保存的 G1、G2 與 PPL aggregate results。
